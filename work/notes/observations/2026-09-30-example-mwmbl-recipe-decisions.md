# example-mwmbl-recipe: in-scope decisions

2026-09-30, task `example-mwmbl-recipe`. Recorded so the reviewer and the owner can ratify or reverse them. The code-level ones are also stated in the comments of `examples/recipes/mwmbl.mjs`, and the user-visible ones in the README ("Example: Mwmbl").

Drift check at launch: the task matched the code and Mwmbl's pages. https://developer.mwmbl.org/ (fetched 2026-09-30) still documents `GET https://api.mwmbl.org/api/v2/search/?q=`, the anonymous tier (1,000 requests a month, 1 request per second, tied to the IP address, no key), the key as the `api_key` query parameter, and 429 over quota. https://mwmbl.org/terms (effective 2025-05-10) forbids "scraping, excessive automated queries" and puts the dataset under CC BY-NC-SA 4.0. `examples/` is in no workspace package (`pnpm-workspace.yaml` lists `packages/*` only) and is already in `NON_SHIPPED_PREFIXES` of `scripts/copy-publish-assets.mjs` (Marginalia task), so the README link to it is rewritten to GitHub on publish with no script change. As in earlier tasks, the body sat in `work/tasks/backlog/` and the spec is at `work/specs/tasked/searchcast-monorepo.md`, not `work/specs/ready/`.

Live check (the one allowed): 2026-09-30T20:26Z, plain `curl` (not searchcast's transport), no key, `q=linear%20b`: HTTP 200, `{"query": "linear b", "number_of_results": 71, "results": [...]}`, each result with `url, title, title_highlights, content, content_highlights, engine, score`; the first was `Linear B` at `https://en.wikipedia.org/wiki/Linear_B`. Some results have an empty `content`. The test fake mirrors this shape.

## Decisions

1. **HTTP 503 is detected by matching `HTTP 503` in the `transport` error of `ctx.http.json`**, the same mechanism (and the same dependency on `code.ts`'s message wording) as the Marginalia example, decision 1 of `2026-09-29-example-marginalia-code-recipe-decisions.md`. Mwmbl does not document 503; the task asks for it as overload. 429 is already `blocked` in `ctx.http`. Touches: nothing outside the example.
2. **The recipe cuts to `ctx.maxResults` itself, after filtering unusable entries**, with `slice(0, maxResults)` exactly as the engine chain does (`chain.ts`), since the API has no documented count parameter. No count parameter is sent. Alternative: rely on the chain's cut only (the task asks for the cut in the recipe). The test checks the cut both through the chain and by calling the recipe directly (the chain would hide a missing recipe cut).
3. **Tolerant result mapping, as in the Marginalia example:** entries without a string `url` are skipped, an empty `title` falls back to the `url`, an empty `content` gives no `snippet` (the live answer had empty contents). The highlight, `engine` and `score` fields are dropped.
4. **The key is read from `MWMBL_API_KEY` at each search, not at load time; an empty value sends no key.** It is URL-encoded after `q`. Because it is in the URL, it appears in searchcast's error messages; the README and the module comment say so.
5. **No request pacing in the recipe.** The anonymous 1 request per second limit is left to the caller (said in the README and the module comment); a 429 starts searchcast's cooldown. Pacing would need state across searches (the session) and a wait inside a search, which is more than an example should carry. Alternative: a minimum interval kept in `ctx.session`.
6. **No changeset.** `examples/` is in no package. The README change reaches the published `searchcast` README at its next release without a changeset of its own, as with the Marginalia example (commit 8c2622b had none).
7. **The test fake names no real engine:** the per-result `engine` field (the live answer had real names there) is `engine-a` in the fixtures.
