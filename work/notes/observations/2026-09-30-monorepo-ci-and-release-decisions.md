# Decisions made while building monorepo-ci-and-release (2026-09-30)

Recorded for the `monorepo-ci-and-release` done record. Reality check first: the task's premises held. The two workflows, the pending changesets (plan: `searchcast` 0.2.0, `@searchcast/browser` 0.1.0, `@searchcast/recipe` 0.1.0), the partial pack tests named in the freshness note, and the two CI skips named in the forward-note (the Xvfb case and the SearXNG case of `packages/searchcast/test/serve.test.ts`; confirmed in the last CI log: 508 passed, 2 skipped) were all as described. The scoped names are on npm at 0.0.0 only (checked with `npm view`).

1. **The release plan is computed with `@changesets/get-release-plan`, not by running `changeset status`.** It is the function `changeset status` calls (resolved through the root's `@changesets/cli`, so the same version). Why: `changeset status` also diffs against `baseBranch` with git (it fails on a PR checkout without a local `main`) and exits 1 when packages changed without any changeset, which would add a new "every package change needs a changeset" refusal to every PR. This check is only about versions. Alternative: `changeset status --output` with a fetched `main` (rejected for the refusal it adds). Touches: `scripts/release-plan.mjs` only.
2. **`.changeset/config.json` sets `___experimentalUnsafeOptions_WILL_CHANGE_IN_PATCH.onlyUpdatePeerDependentsWhenOutOfRange: true`** (the forward-note's question). Measured with fixtures (kept as tests in `packages/searchcast/test/release-plan.test.ts`): without it, a minor of a peer plans a MAJOR for the dependent even when the dependent widens its peer range in the same release, so a minor of `@searchcast/browser` could never ship without `searchcast` 1.0.0. With it, a widened range plus a `searchcast` minor plans a minor, and a range left as is still plans a major, which the release-plan check refuses. The current plan is unchanged by it. Alternative: leave it off (no way out but a hand-edited plan). Risk: the option is experimental in changesets' naming; the tests pin its behaviour, so a changesets update that changes it fails the gate. Recorded in the README's Release section too.
3. **The release-plan check also refuses any planned major**, not only a version >= 1.0.0 (the task says both); for a 0.x package they coincide.
4. **The real-tree test asserts the exact plan only while `.changeset/rename-serpcast-to-searchcast.md` exists**, i.e. until the first Version Packages PR consumes the changesets; after that it asserts only that the check passes. Otherwise the Version Packages PR itself would fail CI.
5. **The pack check uses `pnpm pack --dry-run --json`, not `npm pack --ignore-scripts`** (the technique of the old `pack.test.ts`). Why: the release publishes with pnpm, and `prepack` must run for `searchcast`'s README and LICENSE (copied from the root) to be in the tarball. `packages/searchcast/test/pack.test.ts` now uses the same helper (`packedFiles` from `scripts/pack-check.mjs`), so there is one technique; `packages/recipe/test/package.test.ts` and `packages/browser/test/package.test.ts` stay (they pin API/export shape, not the tarball).
6. **`searchcast`'s `files` gains `CHANGELOG.md`**: the pack check's shape requires it for every package and `searchcast` was the only one without it. A `searchcast` minor changeset (`.changeset/monorepo-ci-and-release.md`) says so; the plan stays 0.2.0.
7. **Pack shape:** exactly README.md, LICENSE, CHANGELOG.md, package.json, the package's `extraFiles`, and otherwise files matching its `allow` patterns (default: `dist/**/*.js|.d.ts` and their maps), each pattern matching at least one file. The LICENSE text must match the license (MIT or AGPL-3.0). Every non-private package under `packages/` must be listed in `PUBLISHABLE`, so the platform packages of `libcurl-platform-packages` cannot be published unchecked (they add an entry with their own `extraFiles`/`allow`).
8. **"No silent skip" is enforced after the fact**, by `scripts/no-skips.mjs` reading each package's vitest JSON report (`pnpm test:ci`), rather than by requiring env variables up front: it catches every skip condition (the native library, Chrome, Xvfb, `systemd-socket-activate`, `unshare`, SearXNG), including future ones. Its `ALLOWED_SKIPS` list is empty.
9. **SearXNG runs in CI** (no named exception needed): SearXNG has no releases, so CI fetches commit `a9d99003344ac3879ec45c56c661283482a92a39` and installs its `requirements.txt` in a virtualenv (a few seconds with wheels), with a wrapper that sets `PYTHONPATH`. Xvfb comes from apt. With a local libcurl-impersonate, Chromium, Xvfb and that SearXNG, `pnpm test:ci` ran all 629 tests with zero skips.
10. **Root scripts:** `pnpm test` = `check:release`, every package's tests, `check:pack` (so `verify` in `dorfl.json` runs both guards unchanged); `pnpm test:ci` adds the JSON reports and `no-skips`; `release:ci` runs `check:release` and `check:pack` before `changeset publish`. The script tests live in `packages/searchcast/test/` next to `copy-publish-assets.test.ts`, the existing precedent for testing root scripts.
