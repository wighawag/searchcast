# Decisions of `browser-no-source-maps` (2026-09-30)

1. **No changeset.** The pending `.changeset/browser-library-package.md` minor already makes `@searchcast/browser` 0.1.0 its first release under this name, and no version of it has shipped with the maps, so there is nothing for a user to read about. A patch changeset on top would still plan 0.1.0 but would add a changelog line describing a defect that never reached anyone. Alternative considered: a patch changeset ("no source maps in the tarball"). Touches only the release notes of `@searchcast/browser`; the release plan is unchanged (searchcast 0.2.0, @searchcast/browser 0.1.0, @searchcast/recipe 0.1.0, platform packages 0.1.0).
2. **`packages/browser/tsconfig.json` keeps only `lib` on top of the base** (`ES2023`, `dom`, `dom.iterable`). The build needs `dom`: without it `src/probe.ts` (page-side code) fails to type-check (`document`, `location`, `Element`). `dom.iterable` is kept as it was, since dropping it is a type-checking change outside this task. Everything else (`target`, `module`, `strict`, ...) now comes from `tsconfig.base.json` and was identical.
3. **`DIST_FILES` in `scripts/pack-check.mjs` no longer accepts `.map`** for any package, so a map in a tarball is reported as an unexpected file. A `dist/` left over from an older build still holds the maps (tsc does not clean), so a local checkout needs `rm -rf packages/browser/dist` before the pack check passes; CI builds fresh.
