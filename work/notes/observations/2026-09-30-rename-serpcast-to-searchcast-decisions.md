# Decisions made while building rename-serpcast-to-searchcast (2026-09-30)

Recorded for the `rename-serpcast-to-searchcast` done record. Reality check first: the task's premises held. `packages/searchcast` was npm `serpcast` 0.6.0 with a `serpcast` bin, the optional peer was already `@searchcast/browser` (`>=0.1.0 <0.2.0`, plus the `workspace:^` devDependency, left untouched), the root README's library-mode paragraph already named `@searchcast/browser`, and the exported names containing `Serpcast` were exactly the five of ADR 0005 (`SerpcastError`, `SerpcastErrorKind`, `createSerpcast`, `Serpcast`, `SerpcastOptions`). `changeset status --verbose` plans `searchcast` 0.2.0, `@searchcast/browser` 0.1.0, `@searchcast/recipe` 0.1.0, no major.

1. **`src/serpcast.ts` became `src/chain.ts`** (and `test/serpcast*.test.ts` became `test/chain*.test.ts`), not `src/searchcast.ts`: in this package "searchcast" already names the browser side (`searchcast-endpoint.ts`, the `searchcast` option and engine field), and the module is the engine chain. Touches: the LOC table in the README.
2. **New module `src/data-dir.ts`**: `dataDir`, the new `oldDataDir`, `libraryFileName` (moved from `libcurl.ts`, still exported from the main entry) and the new `oldDataDirHits`. A module of its own so `libcurl.ts`, `recipes.ts` and `doctor.ts` share it without an import cycle, and so the main entry still reaches no download code (the import-walk test is unchanged). The concept is named "old data directory", ADR 0005's wording (CONTEXT.md gains **Data directory** and **Old data directory**); alternative "legacy". `oldDataDir` and `oldDataDirHits` are marked `@deprecated`, since they go with the fallback. Both are exported from `searchcast` and `searchcast/install` for webveil.
3. **`LibrarySource` gains `'SEARCHCAST_LIBCURL_PATH'`, `'SERPCAST_LIBCURL_PATH'` and `'old data directory'`** (the value `'data directory'` still means the new one). `doctor`'s `from:` line for the two old sources names the new name to use. The platform-package source is left to `libcurl-platform-packages`.
4. **What doctor reports and the `mv` command.** A "hit" is an item present in the old directory and missing from the new one: the library file, and each recipe set by name (other files in the old directory are ignored). The report gets `oldDataDir: {dir, newDir, items, command}` and two lines, `old data dir:` and `move with:`. The command is `mv '<old>' '<new>'` when the new directory does not exist, else `mkdir -p '<new>/recipes'` (only when sets are listed) then one `mv` per item, joined with `&&`, paths single-quoted for a POSIX shell (no Windows form). The fallback does not make the report unhealthy (`healthy()` unchanged). Alternatives: always print per-item commands (longer for the common case), or treat a fallback as unhealthy (would fail `doctor` for a working setup). Touches: the doctor report shape (`searchcast/install`).
5. **Recipe-set fallback through a new `recipeSetDir(name, env?)`**, exported from both entries: the set's directory in the new recipes directory, else in the old one, else `undefined` (a name that is not one set-name segment is never found). `recipesDir()` keeps meaning the new base, where `install-recipes` writes. So an embedder that still does `join(recipesDir(), set)` gets no fallback and must switch to `recipeSetDir`; the README says so. Alternative: make `recipesDir()` return the old base when the new one is missing (rejected: it is also the writers' location, and it would pick a whole directory instead of a set by name as the task asks).
6. **`recipes list`** without `--dir` prints the new directory's sets, then (only when there are any) the old directory's under their own header, each marked `used` or `not used: <new set> wins`; with `--dir` it lists only that directory, as before. New export `formatInstalledRecipeSets(env?)`; `formatRecipeSets` gained two optional parameters (header, per-set note), so its existing calls are unchanged.
7. **`install-libcurl` ignores a library in the old directory**: it is not "already installed", so the command downloads and installs into the new directory (the old file stays, now shadowed). Alternatives: copy it from the old directory (a move/copy of user files, rejected by ADR 0005), or report `unchanged` (would leave the user on the fallback forever).
8. **`SearchcastError.name` is `'SearchcastError'`.** The alias is the same class, so the old name cannot keep `name === 'SerpcastError'`; code comparing `error.name` (rather than `instanceof` or `kind`) breaks. Said in the changeset.
9. **Aliases live in `src/deprecated.ts`**, one file to delete with the fallback. Runtime identity is tested (`toBe`, `instanceof` both ways, the built package's exports); type identity uses `expectTypeOf`, which only bites when the tests are type-checked (see the separate observation `2026-09-30-tests-not-type-checked.md`); it was checked by hand with `tsc --noEmit` on `test/index.test.ts`, including that a wrong alias fails.
10. **Message changes besides the `serpcast:` to `searchcast:` prefix:** the `form` recipe error now says `run it through a browser engine (@searchcast/browser)` (it said "through searchcast", which now names this package); the download `user-agent` is `searchcast`; the temporary browser profile prefix is `searchcast-profile-`.
11. **Kept on purpose:** the `searchcast` option of `createSearchcast` and the `searchcast` field of a browser engine (ADR 0005 does not rename them; renaming would break every browser engine definition). They now read as "the browser runner's options" inside the `searchcast` package, which is a little odd; a later rename would need its own ADR entry and a fallback. The state-store key `serpcast/sessions` is unchanged (ADR 0005).
12. **ADR and findings notes:** the one added line is a blockquote placed above the `# title` of ADRs 0001 to 0004, and right after the YAML front matter of each findings note (above the title), so the front matter stays valid.
13. **Real engine names:** Bing was replaced by placeholders (`engine-a`, "one measured engine") in the README, the package CHANGELOG (one history entry's example), `src/decoy.ts` and the tests. Kept: SearXNG (the metasearch software this integrates with, not an engine), "Google Chrome" (a browser brand inside `sec-ch-ua`), Wikipedia (a result site in decoy fixtures, not a search engine) and the Marginalia example.
14. **CHANGELOG:** the title is `# searchcast` (changesets inserts new entries under it) followed by a line saying the entries 0.1.0 to 0.6.0 were released as `serpcast` and that `searchcast` 0.1.x was the browser runner, as the recipe and browser packages did.
